# saml2-sp

Java service provider for SAML 2.0 Web Browser SSO, plus a Shared Signals poll receiver. Version 0.1.1. MIT. `develop` and `main` are one commit. A pull request merged into `main` publishes the library (`library/` only; the demo never) to Maven Central after the test workflow succeeds on that commit. A direct push does not. `publish.yml` runs `mvn -Prelease -f library/pom.xml deploy` in the Maven container: the `release` profile adds the sources and javadoc jars, a GPG signature on every file, and the Central publishing plugin, which uploads, publishes and waits until the release is live. Maven Central has no trusted publishing, so the job uses four repository secrets: `CENTRAL_TOKEN_USERNAME` and `CENTRAL_TOKEN_PASSWORD` (a Central Portal user token) and `GPG_PRIVATE_KEY` and `GPG_PASSPHRASE` (the release signing key, whose public half is on a public key server). A release on Central is permanent: a version already there is skipped, and the next release is a new version in `VERSION` and the three poms. `-Dcentral.skipPublishing=true` builds and signs everything and uploads nothing.

## Usage

`ServiceProvider.fromFile("saml.json")`, then `login` and `acs(method, url, body, requestId)`. JSON keys match the Node configuration (`entityId`, `acsUrl`, `privateKey`, `certificate`, `idpMetadata`, bindings, `signals`, `ssf`). Methods match the TypeScript names (`fromFile`, `login`, `acs`, `postFormHtml`). Group `com.iyasec`, artifact `saml2-sp`, packages under `com.iyasec.saml`.

`signals` omitted or `true` keeps the receiver available and is omitted from the resolved configuration. `false` does not start a receiver and does not require transmitter metadata, and the resolved configuration includes `signals: false`. A non-boolean raises `signals must be true or false`. The flag does not change the AuthnRequest: SAML does not send OAuth scopes.

Request bindings are `redirect` and `post`. Response bindings are `post`, `redirect`, and `artifact`. Artifact resolution is a signed SOAP `ArtifactResolve`. HTTP-Redirect query signatures use RSA-SHA256 (`http://www.w3.org/2001/04/xmldsig-more#rsa-sha256`). Success is `urn:oasis:names:tc:SAML:2.0:status:Success`. `com.iyasec.saml.Cli generate-keys` writes a self-signed RSA certificate.

## Errors

`Caught.error` records a caught exception through `java.lang.System.Logger`, including the stack, and the method then throws the `SamlError` it already threw. The caught exception is the cause. `Caught.warn` is the same record when the method recovers and does not throw: a later signing key, a poll retry, a false verification, sign-out cleanup, or a handler that must still acknowledge the Security Event Token. A `catch (SamlError)` that only throws that error again is not logged a second time.

## Tests

```bash
docker build --target test .
```

The `test` stage runs `mvn -B test` in `maven:3.9.6-eclipse-temurin-17`, with `python3` and `openssl` installed for `TrustChainTest` (the install script's code and `scripts/trust_chain.py` write the four-certificate chain to `idpCa`'s path; the library trusts the provider and a reissued leaf through that file, and refuses a forged leaf followed by the real CA certificates and the right chain under the wrong host name). GitHub Actions uses that command. Do not run Maven on the host. The demo stage packages with `-DskipTests` in its own Maven image. Signatures and decryption are real (JDK ciphers, Apache Santuario exclusive canonicalization). Nimbus JOSE verifies Shared Signals JWS only. The stub identity provider is in `src/test/java/com/iyasec/saml/StubIdp.java`. The stub tests do not start iya-sts. Java 17.

`python3 scripts/live_iya_sts.py` signs the demo in to iya-sts and checks credential-change and session-revoked on `GET /live-status`. It builds the demo the way a user does: in a scratch copy of the checkout, the install script first (writing the key pair, the metadata and the `idpCa` chain; its Java CLI runs in the demo image), then the image build, then the run with only `sp.key`, `sp.crt` and `idp-metadata.xml` mounted. No CA mount, no `idpCa` rewrite; it checks the image holds the chain and no key. Secrets go to docker as `-e NAME`; no log line carries a sign-in URL. The nightly workflow runs the unit suite and that script once every 24 hours. Neither binds port 3000, 8081 or 18481-18495; the defaults are 18555 and 18655. Push CI stays the unit suite.

`idpCa` (`file:generated/idp-ca.pem`) is the iya-sts TLS listener CA trust chain. `scripts/configure_iya_sts.py` writes the whole chain there on every run through `scripts/trust_chain.py` (`GET /tls/server-certificate`, falling back to the handshake). `Backchannel` makes every block a PKIX trust anchor (a presented leaf counts only if it is itself in the file; otherwise the chain must verify to an anchor), and `HttpClient` still verifies the host name. The demo image bakes the file in (`COPY demo demo` after the compile; `.dockerignore` admits only that file of `demo/generated`, so keys and metadata never enter an image, and a build without it succeeds). Rebuild the image after re-running the install script against a different iya-sts. Do not replace the directory COPY with one that names the file or globs for it: both builders fail when it is absent. A generated test-user password goes to `demo/generated/<user>.password` (mode 0600), never to the output.

**Plain http (#17).** `Backchannel.send` is the one place every fetch goes through (metadata URL, `ArtifactResolve`, SSF configuration, JWKS, stream and poll). `refusePlainHttpOffLoopback` refuses plain `http://` to a host that is not loopback (`127.0.0.0/8`, `::1`, `localhost`) before connecting, without resolving a name, naming only the scheme and host[:port]; userinfo is never loopback. Redirects are followed by hand (`Redirect.NEVER`, at most five hops, the JDK's method rules, never https to http) so each hop gets the same check. A URL or `Location` holding whitespace or a control character is refused first (`refuseWhitespaceOrControl`), so no two parsers can disagree about the host. No opt-out. `PlainHttpTest` covers it; `http://0.0.0.0:<port>` reaches a 127.0.0.1 listener on Linux, so an empty backlog proves no connection was opened.

## Layout

Two Maven modules under an aggregator `pom.xml`, which builds both and is never published; keep its version, the library's and the demo's equal to `VERSION`. `library/` is `com.iyasec:saml2-sp`, the library alone: its `pom.xml` inherits nothing, so it is complete as published, and its jar carries no demo class. `library/src/main/java/com/iyasec/saml/` library, `ssf/` receiver, `library/src/test/java/`; `library/src/test-fixtures` holds `StubIdp`, which both modules' tests compile (build-helper) and no published jar carries. `demo/` is `com.iyasec:saml2-sp-demo`, never published: `com.iyasec.saml.demo.Demo`, and `TrustChainTest` (run from the repository root); its jar and `target/dependency` (the library among them) are what the image runs as `saml2-sp.jar:dependency/*`. Then `scripts/configure_iya_sts.py`, `scripts/live_iya_sts.py`, `Dockerfile`, `docker-compose.yml`, `.github/workflows/nightly.yml`. The image name is `saml2-sp-java-demo`. Compose uses `network_mode: host`, service `saml-demo`, and `ENV PORT=3000` in the image. The health check is `http://127.0.0.1:${PORT}/healthz`. The live script never binds port 3000 or 8081.

## Demo

`docker compose up --build`. `GET /healthz` is `200` with body `ok` and does not load the service provider. Pages: sign-in, `/login` (redirect or POST form), `/saml/acs`, logout of one account or every account, metadata, and per-account Shared Signals events. `GET /live-status` does not need an account id. It is JSON: `signedIn` is true when any local account session exists, plus `subject`, the receiver state, and accepted events (`type` and `jti` only). No tokens. Loopback entityID and assertion-consumer URLs follow `PORT`. Other hosts stay as written. `PUBLIC_URL` or `--public-url` replaces the origin and keeps the path. The default `http://localhost:3000` is not an explicit public URL. `demo/saml.json` uses `file:` placeholders and omits `signals`. Do not commit `demo/generated/`. The live script and the nightly workflow never bind port 3000 or 8081.

## Signals

With an `ssf` block and without `"signals": false`, the demo starts one poll receiver on the service provider's certificate (mutual TLS). The first poll runs on a background thread so a down transmitter does not block a page. `scripts/configure_iya_sts.py` registers the SP metadata, pins AES-256-GCM / RSA-OAEP, turns on multiple accounts, and, unless signals are off, grants `ssf.manage`. The container `PORT` wins over the shell `PORT` at registration. The assertion SessionIndex is not the CAEP session id. On `session-revoked`, the event handler ends this demo's one session and says so. `session-revoked` leaves `signedIn` false.
